# 导出现场包改磁盘保存位置（U11）

- 状态：已实现（U11 全轨收口）
- 日期：2026-11-03
- 依据：G2 收口后按排期开 U11；U10 已解决「开录落盘」，导出仍走浏览器强制下载，现场难指定盘符/旁路目录

## 背景

正式用法是双击壳 EXE。  
录制侧已按 U10 落到 `{壳}\record\日期\*.fcap`。  
「导出现场包」、重演页「另存裁剪」、以及勾选「同时导出 .pcap」仍用 WebView/浏览器式 `download`，常见落点是系统「下载」目录或不可预期提示，现场不好指定 U 盘/工作盘，也不易与 `record\` 旁路放一起交给研发。

## 目标

1. 壳内导出正式 `.fcap` 时，用**原生另存为**选定绝对路径并写入该路径（不以系统下载目录为正式落点）。
2. 可选同时导出 `.pcap` 时，与 `.fcap` **同目录、同基名**落盘（不强制再弹第二次对话框）。
3. 重演页「另存裁剪 .fcap」走同一套磁盘保存体验。
4. 成功后提示中带**实际写入路径**（至少 `.fcap`；若写了 pcap 一并可知）。

## 非目标

- 改 `.fcap` / `.pcap` 格式语义，或 E10/E13 裁剪算法
- 改 U10 开录 `record.start.out` 约定
- 安装向导、默认改到「文档」库、云盘同步
- 强制 `npm run dev` / 无壳浏览器预览具备原生另存为（无壳可保留现下载或手填，正式交付以壳为准）
- 批量导出多会话、自动上传、导出加密
- 离线 JSON 演示包必须改路径（可仍用现下载；连引擎后的正式二进制才是本条主路径）

## 用户故事

1. 作为现场人员，我希望导出现场包时能选 U 盘或 `record\日期\`，以便直接拷走，而不是翻系统「下载」。
2. 作为现场人员，我希望勾选同时导出 pcap 时，两个文件出现在同一目录且基名一致，以免再找一遍。
3. 作为调试人员，我希望裁剪另存也落到我选的路径，行为与导出现场包一致。

## 产品约定（已确认）

| 项 | 约定 |
|----|------|
| 正式落点 | 用户在壳内另存为选定的**绝对路径**；取消另存为 = **不导出**（不静默落到「下载」） |
| 建议目录 | 初始目录优先 `{壳 fieldreplay.exe 所在目录}\record\<YYYY-MM-DD>\`（与 U10 一致；目录不存在则创建） |
| 建议文件名 | 导出现场包：沿用会话标题 / 现有建议名（`.fcap`）；裁剪：保留现有 `_trim_<from>-<to>` 命名习惯 |
| `.pcap` | 与已选 `.fcap` 同目录、同基名改后缀；写失败时 `.fcap` 仍算成功，提示中说明 pcap 失败原因（与现 toast 语义一致） |
| 覆盖 | 另存为对话框按系统惯例处理重名；本条不另做应用内二次确认 |
| 无壳预览 | 「另存为」可不可用；正式验收以壳为准；勿把浏览器下载当成交付验收通过条件 |
| 与引擎 | 控制面仍可先取字节再落盘，或由壳/引擎写入选定路径；**需求只约束最终落点与取消语义**，不锁定实现侧 |
| 复用 | 优先复用 U10 已有另存为能力（`.fcap` 筛选 / 建议名）；pcap 旁路写入不必再开独立产品入口 |
