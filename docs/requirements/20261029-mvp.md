# FieldReplay MVP 需求

- 状态：已确认
- 日期：2026-10-29

## 背景

基于 Qt 等技术的工业上位机需对接 UDP、TCP、串口、MQTT（后续视频）等现场链路。偶现问题难复现，差旅成本高。需要 **与业务上位机解耦** 的通用录放工具：现场记录设备发来的数据，实验室按时间轴灌回上位机，尽可能还原现场。

## 目标

1. 现场：工具作为 **数据接收器**，顶替上位机接收多通道数据并落盘。
2. 实验室：工具作为 **设备模拟器**，将录制包按相对时间戳重放给真实上位机。
3. 保真优先：原始字节 + 统一时间基；热路径高性能写盘。
4. 任意上位机项目可用，不耦合具体业务协议解析。
5. Windows 下单入口双击即可运行（绿色目录 + 主程序可接受）。

## 非目标

- 透明代理 / 旁路嗅探 / 依赖 Wireshark·tcpdump 才能录
- 替代 Wireshark 做深度协议分析
- MVP 内实现视频流录放
- 业务协议强制解析（Modbus 等仅可作后续可选提示）
- 修改各业务上位机源码才能对接（通过改指向 IP/端口/串口即可）

## 角色与模式

| 模式 | 工具扮演 | 说明 |
|------|----------|------|
| 录制 | 原上位机 | 设备改指向本工具；按通道配置收数据 |
| 重放 | 原设备 | 上位机配置尽量不变，指向本工具或虚拟串口对端 |

## 用户故事

1. 作为现场调试人员，我希望配置若干 UDP/串口/TCP 通道并一键开始录制，以便在上位机不在场时仍能收下设备数据。
2. 作为现场调试人员，我希望结束录制后得到一份可拷贝的数据包，以便发给研发。
3. 作为研发人员，我希望载入该数据包并按时间轴重放，以便本机上位机复现现场行为。
4. 作为研发人员，我希望 TCP 通道可配置服务端或客户端，以便覆盖现有上位机两种接法。
5. 作为现场/研发人员，我希望能录放 MQTT 主题消息，以便覆盖经 Broker 上报的现场数据。

## MVP 功能范围

### 通道

| 通道 | 优先级 | 要点 |
|------|--------|------|
| UDP | MVP | 多路；录：bind 收；放：按时间戳发往目标 IP:port |
| 串口 | MVP | 录：打开实口收；放：写实口或虚拟串口对 |
| TCP | MVP | 角色可配 server/client；录连接事件+双向字节流；放时角色对调 |
| MQTT | MVP 之后、视频之前 | 录：连 Broker 订阅（顶替上位机）；放：按时间轴向 Broker/主题发布；存 topic+payload+时间戳 |
| 视频 | 后置（分阶段） | E7a=RTP/UDP 原始块；RTSP 见 `20261030-video.md` |

### 录制

- 统一相对时间戳（建议微秒级）与可选墙钟起点
- 原始 payload 无损写入会话文件
- UI 显示通道速率、计数、连接状态；报文预览仅为最近窗口，不阻塞写盘
- 导出/保存完整会话包（含通道元数据）

### 重放

- 按相对时间戳调度发送；支持倍速（实现阶段可先 1x，倍速为增强）
- UDP/串口/TCP/MQTT 按通道配置映射到本机目标
- TCP：重放侧角色为录制侧的对端（工具演设备）
- MQTT：重放侧按录制时的 topic（可改写）发布 payload

### 界面（当前优先，先于引擎）

- 视觉与交互尽量对齐：`Downloads\fieldreplay---上位机现场数据录制与高保真重演工作台 (1)`
- 信息架构：录制 / 重演 / 报文（三 Tab）；含 UDP、串口、TCP、MQTT 配置与筛选（视频可后置灰显）
- 窗体：无系统边框，使用自定义标题栏（最小化 / 最大化 / 关闭）；上位机对接不单独占 Tab（重演时改指向即可）
- **报文（帧数据检查）**：通用原始帧浏览（筛选、HEX/ASCII、通道与传输元数据）；不展示业务协议字段解包
- 本阶段允许 mock 数据；不以真实 IO 为完成条件
- 不要求与稿件绝对像素级一致，但主路径、分区与关键文案应对齐
- 开发期可用浏览器预览 UI；**验收与交付以单入口应用为准**（见「验收标准」）

## 验收标准

- [x] 仅用本工具（不靠透明代理）可对至少 1 路 UDP + 1 路串口完成录制并生成会话文件（`self-check` / `io_accept`：UDP 真套接字；串口内存环回；实口另手测）
- [x] 同一会话文件可对本地上位机（或测试接收程序）按原间隔重放 UDP 载荷，抽查字节一致（环回 + 间隔墙钟抽查）
- [x] TCP 通道可配置为 server 或 client 完成录制；重放时工具以对端角色工作，上位机仍按原角色连接（双向环回自检）
- [x] 持续高速率 UDP 灌入时，写盘与时间戳仍连续；UI 卡顿不导致停止收包（热路径在引擎进程；`io_accept` 2000 帧连续写盘；录制侧 SO_RCVBUF 放大）
- [x] Windows 下通过双击主程序进入录/放界面，无需先手动起浏览器或一堆附属服务（E6d：`pack/FieldReplay/fieldreplay.exe`）
- [x] 仓库具备 README、许可证、需求/设计文档与进度本，便于开源协作与新会话接续
