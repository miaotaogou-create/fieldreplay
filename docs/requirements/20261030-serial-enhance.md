## 背景

引擎已支持 Windows Win32 实口录放，自检与 `io_accept` 仍走内存环回。UI 串口列表为写死选项，现场易选到不存在的口。实口路径是工业上位机主路径之一，应优先补齐「看得见口、开得住口、有手测清单」。

## 虚口手测清单（com0com 等）

前置：本机已装虚拟串口对驱动（如 [com0com](https://sourceforge.net/projects/com0com/)），并建好一对交叉口（下文以 `COM3`↔`COM4` 为例；以设备管理器 / `serial.list` 实际名为准）。两端波特率须一致（示例 `115200 8N1`）。

### A. 枚举

1. 启动引擎 `serve`（或绿色包），UI 连接引擎。
2. 录制页「添加串口」或重演页串口目标：点刷新后列表应出现 `COM3`、`COM4`。
3. 或 CLI：控制面 `serial.list` 响应含上述口名。

### B. 录制（一端灌、一端录）

1. 引擎录制打开 **COM3**（115200）。
2. 用串口助手 / `ncat` 等打开 **COM4**，向其写入若干可见字节（如两帧 `ping-1` / `ping-2`）。
3. 停止录制并导出 `.fcap`：报文页可见串口通道载荷与灌入一致。

### C. 重放（写到对端口）

1. 载入上一步会话；重放目标选 **COM3**（与录制同侧口亦可；交叉对另一端监听）。
2. 用串口助手打开 **COM4** 监听。
3. 开始重放：COM4 应收到与录制时相同的字节与大致相对时序。

### D. 可选自动化（环境变量门控）

口未被其它程序占用时：

```bat
set FIELDREPLAY_SERIAL_PAIR=COM3,COM4
cd engine
cargo run -- self-check
```

含义：`COMa` = 录制 / 重放写出侧；`COMb` = 灌数 / 监听侧。未设置该变量时 `self-check` **跳过**本项，无 COM 的 CI 不失败。设置了但口不存在、被占用或非交叉对 → 自检失败（有意）。
