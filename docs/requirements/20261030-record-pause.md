# 录制暂停（E16）

- 状态：已确认（分阶段推进；E16b/E16c 已收口）
- 日期：2026-10-30
- 依据：进度本轨道 D；UI 录制页已有暂停入口但引擎拒绝；重放侧 `replay.pause`/`resume` 已落地；待确认项「相对戳冻结 vs 墙钟空洞」

## 背景

现场一次录制常夹杂换料、接线、等人、吃饭等非有效时段。UI 离线 mock 已有「暂停 → 继续」；连上引擎后点暂停只提示「真实引擎录制暂不支持暂停」。  
重放已有「暂停期间墙钟不计入时间轴」；录制侧应对齐同一产品语义，避免「能放不能录」的缺口。  
另立 MQTT mTLS（E15）解决的是少数 Broker 双向证书策略；暂停惠及 **全部通道类型**，且不依赖客户现场证书材料即可验收。

## 选定理由（相对 E15）

| 维度 | E16 录制暂停 | E15 MQTT mTLS |
|------|--------------|---------------|
| 受益面 | UDP/TCP/串口/MQTT/视频全通道 | 仅 MQTT + 要求客户端证书的 Broker |
| 现成缺口 | UI 按钮已在、引擎明确拒 | E9b 已覆盖常见 mqtts（服务端 TLS + CA） |
| 验收条件 | 本机自检即可 | 需夹具发客户端证书；缺真实客户场景 |
| 与既有能力 | 对齐 `replay.pause`；与 E13 trim 互补（在线裁空 vs 离线切窗） | 安全策略加深，非主路径体验 |

**结论：本轮主线为 E16。** E15 仍待命，待出现明确 mTLS 现场再开。

## 用户故事

1. 作为现场调试人员，我希望录制中途暂停后再继续，以便跳过换线/等人时段，导出包里不要出现大段空轴。
2. 作为研发人员，我希望暂停期间时间轴冻结，以便重放时有效片段紧密衔接，不必事后再 trim 掉「人为空窗」。
3. 作为多通道用户，我希望一次暂停作用于整次录制的所有通道，以便共享时间轴不被拆散。

## 产品约定（已确认）

### 相对时间戳策略（拍板）

| 项 | 约定 |
|----|------|
| 策略名 | **相对戳冻结**（与 `replay.pause` 同构：暂停占用的墙钟 **不计入** 会话相对轴） |
| 暂停中 | `relative_us` **不前进**；不向 `.fcap` 写入 data / TCP 事件 / 业务帧 |
| 恢复后 | 相对轴从暂停前的值继续；下一帧 `relative_us ≥` 暂停前最后一帧（同戳允许多条） |
| 墙钟起点 | `start_wall_unix_us` **不变**（仍为 `record.start` 时写入的值） |
| 不采用 | 「墙钟留空洞」：暂停期间仍推进 `relative_us` 但不写帧（会在轴上留空窗，重放空等；与「跳过无效时段」目标相反） |

说明：若用户希望保留真实墙钟空档，应 **不停录** 或事后用 E13 trim 保留空洞两侧；暂停表达的是「这段不要进会话时间轴」。

### 会话与多路

| 项 | 约定 |
|----|------|
| 作用域 | **整次录制**（单路或多路 `channels[]` 同一把会话钟） |
| 互斥 | 仅 `state=recording` 时可 pause/resume；idle / replaying 拒绝 |
| 与 stop | `record.stop` 在 paused 或 recording 均可；stop 结束会话，不要求先 resume |
| 与 marker | 暂停中允许 `session.addMarker`：写入当前（已冻结的）`relative_us`；aux 照常 |

### IO 行为（暂停中）

| 项 | 约定 |
|----|------|
| 连接 | **保持**已打开的通道（UDP socket / TCP / 串口 / MQTT / 视频收流不因 pause 主动拆连） |
| 收包 | 继续从内核/对端 **排空读入**，但 **不打戳、不写盘、不推** `record.packet`（避免 UDP/串口缓冲撑满；避免 MQTT 会话因背压异常） |
| 预览 | 暂停期间 UI 预览流暂停推进；`status` 可反映 `paused:true` |
| 计时 UI | 已录「有效时长」按相对轴（冻结）；墙钟墙上时间不必与有效时长一致 |

### 控制面（E16b/c 实现时）

| cmd | 作用 |
|-----|------|
| `record.pause` | 录制中：置 paused；已 paused 可幂等 `already:true` |
| `record.resume` | 暂停中：清 paused，相对轴继续；未 paused 可幂等 |
| `status` | `state=recording` 时增加/保持 `paused` 布尔（与重放 status 对称） |

### UI（E16c）

- 引擎已连接：暂停/继续走真实 `record.pause`/`resume`；去掉「暂不支持暂停」提示。
- 未连接：保留现有 mock 暂停行为。
- 文案：暂停中主按钮区可见「录制已暂停」；可继续或停止并导出。

## 非目标

- 按通道单独暂停
- 暂停时自动插入 marker / 自动 trim
- 暂停时断开并重连通道（保持连接）
- 改变 `.fcap` 格式或 `start_wall_unix_us` 语义
- 录制倍速 / 倒录
- MQTT mTLS、客户端证书（E15）
- `insecure_skip_verify`

## 风险与依赖

- 暂停排空但不写盘：对端若依赖「每包必有业务应答」可能行为异常——本工具本就不做业务协议，可接受；文档可一句提示「暂停期仅丢弃收包」。
- 单路 `record.rs` 与多路 `multi_record.rs` 时钟路径需同时支持冻结，避免只改一侧。
- 与 E13：暂停是在线跳过；trim 是离线裁窗；二者互补，不互相替代。
