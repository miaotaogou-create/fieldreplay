# 视频通道（分阶段）

- 状态：E7a 已收口 / E7b–E7d 待做
- 日期：2026-10-30
- 依据：`PROGRESS.md` E7；与 MVP「视频后置」一致，**不**塞进 MVP 验收

## 背景

现场上位机常接相机（多为 RTSP）。完整 RTSP 信令 + 解封装工作量大，且易引入非 std 依赖。产品原则仍是 **原始字节 + 时间戳、不解业务/不解编码**。

## 目标模型

| 阶段 | ID | 内容 | 非目标 |
|------|-----|------|--------|
| E7a | 本阶段 | **RTP/UDP 数据报**录放；`.fcap` `type=video`；控制面/UI 可启停 | 不解 H.264/HEVC；不做 RTSP 握手；不做画面预览 |
| E7b | 后置 | 控制面/UI 抛光（筛选文案、重演页视频目标区）与文档手测清单 | — |
| E7c | 后置 | 最小 RTSP **客户端拉流**（交织 TCP 或 SETUP 后收 RTP），仍按块落盘 | 不解析 NAL；无画面 |
| E7d | 后置 | 最小 RTSP **服务侧重放**（答 DESCRIBE/SETUP/PLAY 后按时间轴吐块） | 不替代专业流媒体服务器 |

## E7a 角色

| 模式 | 工具扮演 | 说明 |
|------|----------|------|
| 录制 | RTP 接收端 | bind UDP 口收原始数据报（可为 RTP 或任意 UDP 媒体块） |
| 重放 | RTP 发送端 | 按 `relative_us` 发往目标 IP:port（上位机或下游） |

`config_json` 可带可选 `rtsp_url` **仅作现场备注**（E7a 不连 RTSP）。`media` 固定建议 `"rtp_udp"`。

## E7a 验收

- [x] `self-check` 含 video（RTP/UDP）录 → 写盘 → 环回重放，载荷一致
- [x] 控制面 `record.start` / `replay.start` 接受 `type=video` 或 `video_stream`
- [x] UI：可添加/勾选视频通道（bind 口）；引擎已连时可真实录放；报文页显示「视频」
- [x] `.fcap` 通道类型为 `video`（5）；旧文件无 video 通道行为不变

## 非目标（整段 E7）

- MVP 验收回退或改写已勾选项
- 在 UI 内嵌解码播放器
- 强制引入 FFmpeg / GStreamer 作为引擎依赖（若 E7c/d 实在需要，须单独决策）
