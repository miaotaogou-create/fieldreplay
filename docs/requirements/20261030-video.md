# 视频通道（分阶段）

- 状态：E7a / E7b / E7c 已收口；E7d 待做
- 日期：2026-10-30
- 依据：`PROGRESS.md` E7；与 MVP「视频后置」一致，**不**塞进 MVP 验收

## 背景

现场上位机常接相机（多为 RTSP）。完整 RTSP 信令 + 解封装工作量大，且易引入非 std 依赖。产品原则仍是 **原始字节 + 时间戳、不解业务/不解编码**。

## 目标模型

| 阶段 | ID | 内容 | 非目标 |
|------|-----|------|--------|
| E7a | 已收口 | **RTP/UDP 数据报**录放；`.fcap` `type=video`；控制面/UI 可启停 | 不解 H.264/HEVC；不做 RTSP 握手；不做画面预览 |
| E7b | 已收口 | UI 抛光：报文筛选「视频 RTP」、重演页视频目标提示、录制文案；手测清单 | 不改引擎热路径 |
| E7c | 已收口 | 最小 RTSP **客户端拉流**（交织 TCP），仍按块落盘；`media=rtsp_tcp` | 不解析 NAL；无画面；无 UDP 侧 SETUP 收流 |
| E7d | 后置 | 最小 RTSP **服务侧重放**（答 DESCRIBE/SETUP/PLAY 后按时间轴吐块） | 不替代专业流媒体服务器 |

## E7a 角色

| 模式 | 工具扮演 | 说明 |
|------|----------|------|
| 录制 | RTP 接收端 | bind UDP 口收原始数据报（可为 RTP 或任意 UDP 媒体块） |
| 重放 | RTP 发送端 | 按 `relative_us` 发往目标 IP:port（上位机或下游） |

`config_json` 可带可选 `rtsp_url` **仅作现场备注**（E7a 不连 RTSP）。`media` 固定建议 `"rtp_udp"`。

## E7a 验收

- [x] `self-check` 含 video（RTP/UDP）录 → 写盘 → 环回重放，载荷一致
- [x] 控制面 `record.start` / `replay.start` 接受 `type=video` 或 `video_stream`
- [x] UI：可添加/勾选视频通道（bind 口）；引擎已连时可真实录放；报文页显示「视频」
- [x] `.fcap` 通道类型为 `video`（5）；旧文件无 video 通道行为不变

## E7b 验收

- [x] 报文页筛选含「视频 RTP」；详情对 `video_stream` 有不解编码提示
- [x] 重演页：会话含视频通道时目标 Tab 显示「视频 RTP」、推送区文案与默认口 5004
- [x] 录制页：添加通道文案为用户口吻（无内部任务号）；列表展示 bind IP:port
- [x] `npm run lint`（`tsc --noEmit`）通过

## E7c 验收

- [x] `self-check` 含 RTSP 交织拉流录制：迷你服务端 → 写盘载荷一致；`media=rtsp_tcp`
- [x] 控制面：`record.start` 在 `rtsp_url`/`streamUrl` 非空时走 RTSP 客户端（仍 `type=video`\|`video_stream`）
- [x] UI：添加视频通道可填 `rtsp://…`；列表展示 RTSP URL；引擎已连时可真实拉流录制
- [x] CLI：`record --rtsp <url>`；重放仍 `--target` UDP（E7d 前）
- [x] 仍仅标准库；不解 NAL / 无画面预览
