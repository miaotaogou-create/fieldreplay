# MQTT 凭据（E9a）与 TLS（E9b）

- 状态：E9a / E9b 已收口
- 日期：2026-10-30
- 依据：MVP 待确认项「账号密码/TLS」；增强项排序 E9 优先于 E10

## 背景

引擎 MQTT 客户端原先仅明文 TCP；E9a 已补 CONNECT username/password。现场 Broker 常开 `mqtts`（TLS），E9b 补可选 TLS 与自定义 CA。

## 目标模型

| 阶段 | ID | 内容 | 非目标 |
|------|-----|------|--------|
| E9a | 已完成 | CONNECT 可选 username/password；控制面/UI/CLI；迷你 Broker 鉴权自检 | TLS；MQTT 5；加密落盘密码 |
| E9b | 已完成 | 客户端 TLS（`tls` / 自定义 CA / 可选 SNI）；控制面/UI/CLI；迷你 Broker TLS + 自检 | 客户端证书双向认证；`insecure_skip_verify` |

## 用户故事

1. 作为现场调试人员，我希望录制/重放时勾选 TLS 并指定 CA，以便连上要求 mqtts 的现场 Broker。
2. 作为研发人员，我希望未开 TLS 时行为与现网一致，以便实验室明文 Broker 不用改用法。
3. 作为现场人员，当 Broker 填 IP、证书是域名时，我希望可单独指定校验用服务器名（SNI）。

## E9a 验收

- [x] `MqttConfig` 可选 `username` / `password`；`config_json` 缺省兼容旧文件
- [x] 客户端 CONNECT：有用户名则置 Username Flag；有密码则置 Password Flag（须同时有用户名）
- [x] CONNACK `return_code=4`（坏凭据）可读错误
- [x] 控制面 `record.start` / `replay.start` 的 MQTT `config` 可带 `username`/`password`
- [x] UI 录制添加 MQTT、重演 MQTT 目标可填用户名/密码并下发
- [x] CLI：`--mqtt-user` / `--mqtt-password`（record / replay）
- [x] 迷你 Broker 可选鉴权；`self-check` 含「正确凭据通过 / 错误凭据拒绝」
- [x] 仍仅标准库；无凭据路径行为不变

## E9b 验收

- [x] `MqttConfig` 可选 `tls`（bool，缺省 false）、`ca_cert_path`、`tls_server_name`；缺省兼容旧 `config_json`
- [x] `tls=true` 时 TCP 连上后先做 TLS 握手再发 MQTT CONNECT；失败给出可读错误
- [x] 有 `ca_cert_path`：只信该 PEM 内 CA；无路径：用系统根证书（空则 webpki 公共根兜底）
- [x] `tls_server_name` 可选：作 SNI / 证书名校验；缺省用 `broker` 主机名
- [x] 控制面 / UI / CLI 可传上述字段（CLI：`--mqtt-tls` / `--mqtt-ca` / `--mqtt-tls-server-name`）
- [x] 迷你 Broker 可 TLS 监听；`self-check` 含「TLS + 自定义 CA 连通」
- [x] 无 TLS 路径行为与 E9a 一致；依赖为 rustls 系（无 OpenSSL）

## 配置约定

```json
{
  "broker": "192.168.1.10",
  "port": 8883,
  "topic": "factory/line3/#",
  "qos": 0,
  "username": "field",
  "password": "secret",
  "tls": true,
  "ca_cert_path": "C:/certs/factory-ca.pem",
  "tls_server_name": "mqtt.factory.local"
}
```

- `username` / `password` 均可省略（E9a）。仅有 `password` 无 `username` 时忽略密码。
- `tls` 缺省 `false`；文档建议 mqtts 常用口 **8883**，不强制改已写 `port`。
- `ca_cert_path` / `tls_server_name` 仅在 `tls=true` 时有意义。
- 密码与 CA 路径会进入控制面消息与可选写入 `.fcap` 的 `config_json`；按现场敏感资料保管。

## 非目标

- 客户端证书双向认证（可再议）
- `insecure_skip_verify` / 跳过证书校验
- Will 消息、MQTT 5 增强认证
- 内置生产级 Broker（迷你 Broker 仅自检）
