# MQTT 凭据（E9a）与 TLS（E9b 预留）

- 状态：E9a 已收口；E9b 未开始
- 日期：2026-10-30
- 依据：MVP 待确认项「账号密码/TLS」；增强项排序 E9 优先于 E10

## 背景

引擎 MQTT 客户端仅发无用户名/密码的 CONNECT，现场 Broker（EMQX / Mosquitto 等）常开鉴权。TLS 另立 E9b，本阶段只补标准库明文 TCP 上的 username/password。

## 目标模型

| 阶段 | ID | 内容 | 非目标 |
|------|-----|------|--------|
| E9a | 本阶段 | CONNECT 带可选 username/password；`MqttConfig` / 控制面 / UI / CLI 可传；迷你 Broker 可校验；自检覆盖 | TLS；MQTT 5；加密落盘密码 |
| E9b | 后续 | Broker TLS（`mqtts` / 自定义 CA） | 客户端证书双向认证（可再议） |

## 用户故事

1. 作为现场调试人员，我希望录制/重放时填 Broker 账号密码，以便连上要求鉴权的现场 Broker。
2. 作为研发人员，我希望无凭据时行为与现网一致，以便实验室无鉴权 Broker 不用改用法。

## E9a 验收

- [x] `MqttConfig` 可选 `username` / `password`；`config_json` 缺省兼容旧文件
- [x] 客户端 CONNECT：有用户名则置 Username Flag；有密码则置 Password Flag（须同时有用户名）
- [x] CONNACK `return_code=4`（坏凭据）可读错误
- [x] 控制面 `record.start` / `replay.start` 的 MQTT `config` 可带 `username`/`password`
- [x] UI 录制添加 MQTT、重演 MQTT 目标可填用户名/密码并下发
- [x] CLI：`--mqtt-user` / `--mqtt-password`（record / replay）
- [x] 迷你 Broker 可选鉴权；`self-check` 含「正确凭据通过 / 错误凭据拒绝」
- [x] 仍仅标准库；无凭据路径行为不变

## 配置约定

```json
{
  "broker": "192.168.1.10",
  "port": 1883,
  "topic": "factory/line3/#",
  "qos": 0,
  "username": "field",
  "password": "secret"
}
```

`username` / `password` 均可省略。仅有 `password` 无 `username` 时忽略密码（与 MQTT 3.1.1：Password Flag 依赖 Username Flag）。

说明：密码会进入控制面消息与可选写入 `.fcap` 通道 `config_json`；会话文件按现场敏感资料保管。E9a 不做加密落盘。

## 非目标

- TLS / `mqtts`（E9b）
- Will 消息、MQTT 5 增强认证
- 内置生产级 Broker（迷你 Broker 仅自检）
